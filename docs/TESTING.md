# 测试与验证

环境：Windows，Java 25，Fabric Loader 0.19.5。各 Minecraft 目标使用的 Fabric API、ModMenu 与适配源码见 [版本矩阵](COMPATIBILITY.md)。

2026-10-08，维护者确认已完成 1.2 发布前实测验收。以下保留自动化构建结果和已有双客户端运行记录。

## 运行测试

构建并执行单元测试，同时检查联机测试代码是否能够编译：

```powershell
# 构建全部目标（PowerShell 7）
.\scripts\build-java25-versions.ps1
# 构建单个目标
.\gradlew.bat build compileIntegrationJava '-Pminecraft_version=26.3'
```

在两个终端分别运行以下命令，可使用真实开发客户端复现联机测试：

```powershell
# 两个终端使用相同的目标版本
.\gradlew.bat runLanTestHost '-Pminecraft_version=26.3'
.\gradlew.bat runLanTestGuest '-Pminecraft_version=26.3'
```

测试使用项目 `build/versions/<Minecraft>/` 下的独立游戏目录。重跑前，将对应版本的 `lan-test-sync`、`lan-test-host` 和 `lan-test-guest` 目录改名移开，避免读到前次测试的通信文件或存档。通过标记为 `lan-test-sync/host-passed.txt` 与 `guest-passed.txt`；任务正常退出与两个通过标记均存在时，才视为联机通过。`clean` 会删除对应版本的全部构建与测试目录。

PowerShell 中请为 `-Pminecraft_version=...` 加引号，避免带点版本号被拆成多个参数。

死亡统计回归可为两个客户端同时添加 `-Plan_test_stats=missing`（无统计文件）或 `-Plan_test_stats=invalid`（不支持的旧格式）；默认 `valid` 预置当前格式的记录。每次使用相同的新 `-Plan_test_id=<编号>` 隔离两端实例。并行启动前先完成目标版本的 `compileJava compileClientJava compileIntegrationJava processResources processIntegrationResources`；随后两端启动时添加 `-x compileJava -x compileClientJava -x compileIntegrationJava -x processResources -x processIntegrationResources`，避免并发编译改写相同输出。客户端运行期间不再构建其他版本。

## 正版验证和名字统计回归

当前单元测试共 43 项：7 项倒计时、19 项世界备份/恢复、11 项死亡统计、6 项配置读写与校验。倒计时测试包含取消后可重新开始、已触发后不可取消。统计测试覆盖名字大小写合并、改名后分开统计、用户名与 UUID 模式互相独立、UUID 模式改名后沿用记录、拒绝旧 UUID 键而不改写文件、计数递增不溢出，以及安全清除两种统计身份。世界备份/恢复测试覆盖中断事务恢复、锁占用保护、损坏或缺失日志、失败目录保护，以及有限保留时只自动清理较早的成功备份。配置测试确认默认为用户名模式，并可保存、重载 UUID 模式及手动重启确认选项。

26.1.2 的房主实际加载 LAN World Plug-n-Play 2.0.8，通过其 `/onlinemode false` 命令关闭正版验证并保存世界配置；客机使用本模组与 Fabric API。最近一次重新执行的两轮真实死亡重开在用户名模式下通过，服务器正版验证仍关闭，PNP 配置内容保持一致，端口始终为 11514，双方 Gradle 任务正常退出并生成通过标记。

随后在 UUID 模式下再次以 PNP 2.0.8 完成两轮双客户端测试。房主死亡统计文件按两个 UUID 分开记录：客机为 6 次，房主为 1 次；榜单 owner 与 UUID 一致。`online-mode:false`、PNP 世界配置和端口 14630 在两次重开后保持，客机两次自动重连，双方任务与通过标记均成功。

另用不含 PNP 的全新 26.1.2 客户端目录验证原版“对局域网开放”，默认用户名模式下客机和房主各死亡一次并完成两轮重开。端口 14884 保持不变，客机两次自动重连，双方任务与通过标记均成功。

联机测试还会在 LAN 作弊权限关闭时由房主执行手动重开确认流程：`restart` 只创建待确认请求，重复准备会被拒绝，`restart confirm` 才启动倒计时；确认后的倒计时可取消，玩家死亡会使待确认请求失效。测试同时覆盖查看状态和客机执行控制命令被拒绝。随后真实玩家死亡仍能正常启动重置。

本轮 PNP 2.0.8 双客户端运行也覆盖上述命令，LAN 作弊权限关闭，端口 4274 在两次重开后保持，房主与客机两项任务均成功。

2026-10-08 又在全新的 26.1.2 原版 LAN 测试目录中执行最新确认逻辑，使用 Oracle GraalVM 25+37 和 `-XX:-UseJVMCICompiler`。未确认的 5 秒手动重开请求在等待超过 6 秒后仍未启动倒计时或改变种子；随后确认、取消倒计时、重复准备被拒绝、取消后确认被拒绝，以及玩家死亡使待确认请求失效均通过。两轮真实死亡重开始终复用端口 9177，客机两次自动重连成功。启动恢复和房主榜单控制也通过；房主和客机 Gradle 任务均成功退出并生成通过标记。本次未单独等待 60 秒实测确认超时边界。
