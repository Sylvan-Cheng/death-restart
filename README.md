# 死亡重启 / Death Restart

适用于 **Minecraft Java 25 正式版 + Fabric** 的局域网联机模组。房主打开单人存档，选择「对局域网开放」后，任意玩家真正死亡都会触发倒计时（默认 **10 秒**），随后自动更换随机种子、重建整个世界，并再次开放同一个联机端口。

当前维护目标为 **26.1、26.1.1、26.1.2、26.2、26.3**。每个游戏版本使用对应的 JAR，具体依赖与验证记录见 [版本兼容说明](docs/COMPATIBILITY.md)。快照、预发布版、Java 21 的 1.21 系列不在此维护范围内。

## 安装和游玩

1. 安装表中目标 Minecraft 版本、Fabric Loader 0.19.5 或更新版本及对应游戏版本的 Fabric API；运行游戏需要 Java 25。
2. 将 `death-restart-1.2+<游戏版本>.jar` 放入**实际使用的游戏实例**的 `mods` 文件夹。启用版本隔离的 HMCL/PCL 实例应使用该版本自己的 `mods` 文件夹。房主与客机应使用相同游戏版本及对应模组构建。
3. 房主与朋友都安装此模组，房主进入一个世界并「对局域网开放」，朋友照常加入。
4. 有人死亡后，所有在线玩家收到标题与倒计时。界面会跟随 Minecraft 当前语言显示简体中文或 English。默认 10 秒结束后，房主保存旧世界、生成新世界、自动进入新一局并重新开放原端口。客机自动尝试重新连接。

只有房主安装时，死亡倒计时和重置仍然生效；没安装模组的朋友需要在世界重新开放后手动加入。普通未对局域网开放的单人游戏不会触发重置。本版本针对局域网房主设计，不支持独立服务器或 Realms。

重置会短暂断开连接；新世界生成需要额外时间。安装模组的客机每 5 秒重试一次，最多等待 2 分钟，可以在等待界面或连接界面取消。**联机端口保持不变**：房主始终复用重置前的端口；若暂时被占用，会显示提示并持续重试原端口。客机等待超时后也可以手动连接原来的地址和端口。

重开会继承当前局域网的正版验证状态。使用 LAN World Plug-n-Play 关闭正版验证后，新一局仍保持关闭，并保留该模组的世界配置文件 `mcwifipnp.json`。

## 右侧死亡榜
未死亡的玩家显示 0。每次真正死亡都会加 1，包括重置倒计时内发生的后续死亡。

排行榜在每次换种子重开后保留，退出游戏再进入同一存档也继续累计。不同存档分别统计；退出的玩家也保留在榜单上。默认按用户名统计，忽略大小写：同名玩家共享累计次数，切换正版与离线登录模式也沿用同一条记录；改名后视为新玩家。房主可以在 ModMenu 设置里切换为 UUID 模式，按账号统计，改名后仍沿用原记录。两种模式的数据分开保存，切换只更换当前显示的排行榜，不会合并次数；切回原模式可继续查看该模式的数据。榜单按死亡次数从高到低排序，同分时按名字字母顺序排列。使用原版侧边栏同步，没安装模组的客机也能看到死亡榜；屏幕最多显示原版侧边栏支持的 15 行。

统计文件位于房主游戏实例下的 `config/deathrestart/deaths/<存档目录名>.json`，同一文件可保留用户名和 UUID 两种格式的记录。如需从零重新统计，退出这个世界后，将对应统计文件改名移走。不会导入旧版原始 UUID 键格式；遇到不支持的统计文件时，模组会保留原文件、在日志中报告读取失败，并显示本次世界运行期间的临时次数，不会用临时次数覆盖原文件。排行榜会占用原版的右侧计分板位置。

## ModMenu 设置

安装适用于当前 Minecraft 版本的 ModMenu 后，从模组列表选中「死亡重启 / Death Restart」并点击配置按钮即可打开设置页。设置会保存在游戏实例的 `config/deathrestart.json`，并在下次启动时继续使用。ModMenu 是可选依赖，未安装时仍可使用模组或在游戏关闭时编辑 JSON 配置。

设置页采用原版紧凑布局：开关使用复选框，时长、统计身份和备份数量使用预设循环按钮。依次展示重置规则、死亡榜与统计、旧世界备份、客机重连；清除统计单独放在页面末尾的「数据操作」中，并要求确认。鼠标悬停会显示说明。点击「完成」或按 Esc 保存，点击「恢复默认」后仍需保存。主菜单可预设全部选项；客机联机时，房主专用选项变灰，「恢复默认」仅重置本机重连设置。关闭自动重连时，重连间隔和超时控件也会变灰：

- 世界重置倒计时：5、10、15、20、30、45 或 60 秒。
- 手动重启需要确认：房主设置，默认开启。关闭后，`restart` 和 `restart <秒数>` 直接开始倒计时；仅影响新请求，已创建的待确认请求仍需确认或取消，正在进行的倒计时不变。配置字段为 `manualRestartConfirmation`，未安装 ModMenu 时可在游戏关闭后编辑 JSON。
- 倒计时开始提示音、最后 3 秒提示音：分别控制开始时和最后三秒每秒播放的音效，均为房主设置，默认开启。
- 显示死亡榜：房主统一控制所有玩家是否显示。关闭只影响右侧榜单的显示，服务器照常累计死亡次数。
- 死亡统计身份：用户名（默认，忽略大小写）或 UUID。此项由房主设置，两种模式的数据分开保存，切换时不会合并。
- 旧世界备份保留数量：无限、1、3、5、10 或 20 个。默认无限保留；新世界成功启动后只清理更早的成功备份，失败恢复目录永不自动删除。
- 自动重连：控制安装模组的客机是否在重置后自动加入。
- 重连间隔：1、3、5、10 或 15 秒。
- 重连超时：30、60、120 或 300 秒。
- 清除死亡榜：进入存档后的房主可用，确认后清除当前存档的用户名和 UUID 两套统计，在线玩家从 0 重新累计。其他存档不受影响，死亡榜显示开关保持原值；主菜单和客机设置页的按钮不可用。

房主的倒计时设置在下一次死亡时生效；正在进行的倒计时保持原时长。提示音和死亡榜显示由房主决定，并发送给当前在线玩家。自动重连由每位客机自己设置；关闭榜单不会停止房主累计死亡次数。联机端口始终复用重置前的端口，每次重置均保留旧世界备份。

## 游戏内控制命令

房主打开局域网后，可在聊天栏使用 `/deathrestart` 控制当前世界：

- `/deathrestart restart`：按默认倒计时手动重开；默认需确认，关闭「手动重启需要确认」后直接开始倒计时。
- `/deathrestart restart <秒数>`：一次性倒计时覆盖，可选 5、10、15、20、30、45、60；不修改默认设置，是否需要确认由房主设置决定。
- `/deathrestart restart confirm`：有待确认请求时，在准备提示后的 60 秒内确认，真正开始手动重开倒计时。
- `/deathrestart cancel`：取消待确认的手动重开，或取消尚未开始执行的重置倒计时。重置开始后无法取消。
- `/deathrestart status`：查看重置倒计时、统计身份、榜单显示、联机端口和正版验证状态。
- `/deathrestart leaderboard <on|off>`：由房主统一开启或关闭所有玩家的死亡榜显示；关闭后仍会继续累计死亡次数。
- `/deathrestart leaderboard clear`：创建清除当前存档两套死亡统计的请求，不会立即清除。
- `/deathrestart leaderboard clear confirm`：在请求后的 60 秒内确认清除。无论是否关闭手动重启确认，清除统计都必须确认；清除不会影响其他存档，也不会切换榜单显示状态。
- `/deathrestart countdown <秒数>`：修改并保存默认倒计时，允许 5、10、15、20、30、45、60 秒；不需要 ModMenu，在下次死亡时生效，不改变进行中的倒计时。

上述重开、倒计时和状态命令只对当前集成服务器的房主开放；无需开启 LAN 作弊权限，也不能用于独立服务器。

每次重置都会自动备份旧世界。ModMenu 的备份保留数量默认是无限；房主主动设置有限数量后，新世界成功启动时会自动清理较早的常规备份。失败世界和未完成事务引用的备份不会自动删除。

`failed-` 是受保护的目录前缀。如果存档目录本身以 `failed-` 开头，它的成功备份也会受到保护，避免与其他世界的失败恢复目录混淆。

中文与英文跟随 Minecraft 语言设置，无需单独选择模组语言。未安装模组的客机收到英文备用提示；其他语言使用英文回退。完整双语文案见 `TEXT.md`，实际资源位于 `src/main/resources/assets/deathrestart/lang/`。

版本变化见 [CHANGELOG.md](CHANGELOG.md)。

## 重置内容

- **重新开始：** 主世界、下界、末地及其他世界维度、建筑、物品、玩家背包、末影箱、经验、进度、统计、出生点与世界运行数据。即使开启 `keep_inventory`，下一局也会清空旧局背包。
- **保留设置：** 存档名称和目录、难度、难度锁定、极限模式、游戏模式、游戏规则、世界生成类型、结构与奖励箱设置、数据包、世界资源包，以及联机游戏模式、允许作弊选项、正版验证状态与 LAN World Plug-n-Play 世界配置。
- 每一局使用新随机种子，保证与上一局不同。超平坦世界仍然是超平坦，种子变化对其地形的影响由原版决定。
- 不死图腾救活不算死亡；其他模组取消的死亡也不会触发。倒计时中其他人再次死亡不会延长倒计时或重复重置。
- 只在房主进程启动倒计时，客机负责接收重置通知和重新连接，不会修改客机自己的存档。

## 旧世界备份和恢复

每次重开都会将旧世界**完整移入**房主当前游戏实例下的：

```text
death-restart-backups/<原存档目录>-<时间>-<随机编号>/
```

新一局继续使用原存档目录，因此退出游戏后，再打开该存档就是最新一局。默认情况下备份不会自动删除；若在 ModMenu 中选择保留数量，模组会在新世界成功启动后自动删除更早的成功备份。`failed-*` 恢复目录始终保留，长期游玩仍可以在游戏关闭后手动整理。

若需要恢复某一局：先退出这个世界，将 `saves` 中当前同名存档移到其他位置保留，再把目标备份文件夹放回 `saves`，并改为原存档目录名。备份包含原来的地形、所有玩家数据和进度。

重建遇到可捕获的错误时，模组尝试自动恢复旧世界，并显示恢复结果；失败的新世界也会保留在 `death-restart-backups/failed-*`。无法自动恢复时，错误界面和日志会给出旧世界备份的位置。

### 重置中断后的启动恢复

移动旧世界前，模组将重置事务日志写入备份目录下的 `.reset-*.json`，日志只记录当前实例内的目录名。新世界生成完成、房主进入并成功重新开放 LAN 后才提交事务，然后执行备份保留策略。

如果游戏进程在中途崩溃或被关闭，下次启动模组会检查未完成事务，自动将完整旧世界放回原存档目录，并将生成到一半的新世界保留为 `failed-*`。主菜单会显示恢复结果，进入原存档即可继续；不会自动进入存档或重新开放 LAN。恢复中再次中断也可在下次启动继续。

遇到损坏日志、占用中的世界或路径异常时保留文件和事务记录，并提示查看日志及备份目录。完成的新世界不会被后续启动回滚。请保留 `.reset-*.json`，不要在重置期间手动移动相关目录；日志机制针对进程中断，不保证修复磁盘损坏或断电造成的文件系统损坏。

## 构建与验证

```powershell
# JAVA_HOME 应指向 Java 25 JDK
# 默认构建 26.3
.\gradlew.bat build
# 指定游戏版本
.\gradlew.bat build compileIntegrationJava '-Pminecraft_version=26.1.2'
# PowerShell 7：构建并测试所有维护版本
.\scripts\build-java25-versions.ps1
```

安装用 JAR 位于 `build/versions/<游戏版本>/libs/`；带 `-sources` 的 JAR 是源码包。各版本使用独立构建、测试报告和开发游戏目录。GitHub Actions 使用同一份版本矩阵运行构建、单元测试及联机测试代码编译。

单元测试覆盖倒计时、世界备份与恢复、死亡统计和配置读写校验。CI 构建每个版本并编译联机测试代码。各 Minecraft 版本的真实双客户端结果及验证限制见 [docs/TESTING.md](docs/TESTING.md)。
