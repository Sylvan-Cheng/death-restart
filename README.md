# 死亡重启 / Death Restart

适用于 **Minecraft 26.1.2 + Fabric** 的局域网联机模组。房主打开单人存档，选择「对局域网开放」后，任意玩家真正死亡都会触发倒计时（默认 **10 秒**），随后自动更换随机种子、重建整个世界，并再次开放同一个联机端口。

## 安装和游玩

1. 安装 Minecraft 26.1.2、Fabric Loader 0.19.5 或更新版本、Fabric API 0.155.3+26.1.2 或适配 26.1.2 的更新版本；运行游戏需要 Java 25。
2. 将 `death-restart-1.1+26.1.2.jar` 放入**实际使用的游戏实例**的 `mods` 文件夹。启用版本隔离的 HMCL/PCL 实例应使用该版本自己的 `mods` 文件夹。
3. 房主与朋友都安装此模组，房主进入一个世界并「对局域网开放」，朋友照常加入。
4. 有人死亡后，所有在线玩家收到标题与倒计时。界面会跟随 Minecraft 当前语言显示简体中文或 English。默认 10 秒结束后，房主保存旧世界、生成新世界、自动进入新一局并重新开放原端口。客机自动尝试重新连接。

只有房主安装时，死亡倒计时和重置仍然生效；没安装模组的朋友需要在世界重新开放后手动加入。普通未对局域网开放的单人游戏不会触发重置。本版本针对局域网房主设计，不支持独立服务器或 Realms。

重置会短暂断开连接；新世界生成需要额外时间。安装模组的客机每 5 秒重试一次，最多等待 2 分钟，可以在等待界面或连接界面取消。**联机端口保持不变**：房主始终复用重置前的端口；若暂时被占用，会显示提示并持续重试原端口。客机等待超时后也可以手动连接原来的地址和端口。

## 右侧死亡榜
未死亡的玩家显示 0。每次真正死亡都会加 1，包括重置倒计时内发生的后续死亡。

排行榜在每次换种子重开后保留，退出游戏再进入同一存档也继续累计。不同存档分别统计；退出的玩家也保留在榜单上。统计按玩家 UUID 记录，改名不会清空次数。使用原版侧边栏同步，没安装模组的客机也能看到死亡榜；屏幕最多显示原版侧边栏支持的 15 行。

统计文件位于房主游戏实例下的 `config/deathrestart/deaths/<存档目录名>.json`。如需从零重新统计，退出这个世界后，将对应统计文件改名移走。排行榜会占用原版的右侧计分板位置。

## ModMenu 设置

安装适用于 26.1.2 的 ModMenu 18.0.2 后，从模组列表选中「死亡重启 / Death Restart」并点击配置按钮即可打开设置页。设置会保存在游戏实例的 `config/deathrestart.json`，并在下次启动时继续使用。ModMenu 是可选依赖，未安装时仍可使用模组或在游戏关闭时编辑 JSON 配置。

设置页按重置规则、客机重连、数据与显示分组；鼠标悬停会显示说明。点击「完成」或按 Esc 保存，点击「恢复默认」后仍需保存。关闭自动重连时，重连间隔和超时控件会变灰：

- 世界重置倒计时：5、10、15、20、30、45 或 60 秒。
- 自动重连：控制安装模组的客机是否在重置后自动加入。
- 重连间隔：1、3、5、10 或 15 秒。
- 重连超时：30、60、120 或 300 秒。
- 显示死亡榜：只控制显示，隐藏期间仍累计死亡次数。启用时占用原版侧边栏；关闭时恢复此前被替换且仍存在的目标。如果其他系统已接管侧边栏，关闭时保留其当前目标。

房主的倒计时设置在下一次死亡时生效；正在进行的倒计时保持原时长。重连选项由每位客机自己设置，在下一次世界重置时生效。死亡榜由房主控制，保存后更新显示。联机端口始终复用重置前的端口，每次重置均保留旧世界备份。

中文与英文跟随 Minecraft 语言设置，无需单独选择模组语言。未安装模组的客机收到英文备用提示；其他语言使用英文回退。完整双语文案见 `TEXT.md`，实际资源位于 `src/main/resources/assets/deathrestart/lang/`。

版本变化见 [CHANGELOG.md](CHANGELOG.md)。

## 重置内容

- **重新开始：** 主世界、下界、末地及其他世界维度、建筑、物品、玩家背包、末影箱、经验、进度、统计、出生点与世界运行数据。即使开启 `keep_inventory`，下一局也会清空旧局背包。
- **保留设置：** 存档名称和目录、难度、难度锁定、极限模式、游戏模式、游戏规则、世界生成类型、结构与奖励箱设置、数据包、世界资源包，以及联机游戏模式和允许作弊选项。
- 每一局使用新随机种子，保证与上一局不同。超平坦世界仍然是超平坦，种子变化对其地形的影响由原版决定。
- 不死图腾救活不算死亡；其他模组取消的死亡也不会触发。倒计时中其他人再次死亡不会延长倒计时或重复重置。
- 只在房主进程启动倒计时，客机负责接收重置通知和重新连接，不会修改客机自己的存档。

## 旧世界备份和恢复

每次重开都会将旧世界**完整移入**房主当前游戏实例下的：

```text
death-restart-backups/<原存档目录>-<时间>-<随机编号>/
```

新一局继续使用原存档目录，因此退出游戏后，再打开该存档就是最新一局。备份不会自动删除，长期游玩可以在游戏关闭后整理旧备份。

若需要恢复某一局：先退出这个世界，将 `saves` 中当前同名存档移到其他位置保留，再把目标备份文件夹放回 `saves`，并改为原存档目录名。备份包含原来的地形、所有玩家数据和进度。

重建遇到可捕获的错误时，模组尝试自动恢复旧世界，并显示恢复结果；失败的新世界也会保留在 `death-restart-backups/failed-*`。无法自动恢复时，错误界面和日志会给出旧世界备份的位置。

## 构建与验证

```powershell
# JAVA_HOME 应指向 Java 25 JDK
.\gradlew.bat build
```

安装用 JAR 位于 `build/libs/`；带 `-sources` 的 JAR 是源码包。

单元测试覆盖倒计时、世界备份与恢复、死亡统计和配置读写校验。联机测试运行方法、验证范围与截图见 [docs/TESTING.md](docs/TESTING.md)。
